# Running custom apps on the Bolt EUV head unit

This is the heart of the project. Read the "hard truths" in the README first.

## The runtime: NGI (Next-Gen Infotainment), HTML5

The Bolt EUV's QNX head unit runs GM's **NGI** app framework. Third-party (and
GM's own) apps are **web apps** — HTML5 + CSS + JavaScript — running in an
on-device web runtime, talking to the car through an **NGI JavaScript API**
(nearly 400 vehicle data points: speed, location, HVAC, etc.). This is the same
model GM opened to developers in 2017 for MyLink / IntelliLink / CUE and carried
into Infotainment 3.

**There is no APK, no Play Store, no ADB.** Anyone telling you to sideload an
APK is describing an Android head unit — a different product.

## What a valid app is

A directory containing at minimum:

```
myapp/
  index.html        # entry point (manifest "main")
  Icon.png          # launcher icon (manifest "icon")
  gmapp.json        # the manifest
  src/  dist/        # source / built output
```

### `gmapp.json` (verified sample)

```json
{
  "name": "NGI GM APLLICATION",
  "id": "98123628",
  "template": "Blank",
  "version": "0.0.0",
  "src": "src",
  "dist": "dist",
  "main": "index.html",
  "icon": "Icon.png",
  "developer": "SALMA LARGO & YOUNES MOUKAFIH",
  "category": "General",
  "type": "RemoteHigh",
  "description": "Generated by ngi-sdk"
}
```

Field notes:
- `main` — HTML entry point. Confirms the web runtime.
- `type` — app trust/hosting class. `RemoteHigh` = remotely-hosted, higher
  privilege. Other classes exist (local vs. remote, low vs. high). **Confirm the
  full enum** from the SDK docs — this governs what APIs an app may call and is
  likely tied to signing/allowlisting on the unit.
- `id` — numeric app id (the AppShop catalog key).
- `category` / `template` — cosmetic / scaffolding.

## Build & test on a laptop today (no car)

GM's `ngi-sdk` is a Node.js package (distributed as a `.tgz` that unpacks to
`package/`). It includes a **local simulator** to run your app and fake the ~400
vehicle data points. Rough flow (confirm against the SDK's own README):

```sh
# after obtaining the ngi-sdk .tgz
npm install -g ./package        # or: npm i -g ngi-sdk
ngi-sdk create myapp            # scaffolds index.html + gmapp.json
cd myapp
ngi-sdk run                     # launches the simulator
```

Do this first — it costs nothing and produces a real, runnable app bundle that
is exactly what we later need to place on the unit.

## Why we still need the "unlock" — the front door is closed

GM **shut down the NGI AppShop and dev-client servers on 2025-09-30** for
2016–2021-era NGI vehicles. Consequences:

- You can no longer register a VIN, get the **GM Dev Client**, or have an
  approved app appear in the in-vehicle **AppShop**.
- Apps already installed keep running; a delete or factory reset is permanent.

So the sanctioned "push an app to the car" pipe is gone. The runtime that
executes NGI apps is **still on the unit**. The gap we must bridge:

> Place a valid NGI app bundle into wherever the unit stores installed apps, and
> register it in whatever catalog/db the launcher reads — manually doing what the
> AppShop used to do over the air.

That requires filesystem write access to the QNX system, which is the extraction
/ console / debug-menu work in [FIRMWARE.md](FIRMWARE.md) and
[NEXT-STEPS.md](NEXT-STEPS.md).
